# tg-sticker-doom

Эксперимент с одним глобальным экземпляром DOOM, экран и управление которого
живут непосредственно в статическом стикерпаке Telegram.

Текущая версия включает проверенный probe обновления пака, headless DoomGeneric,
рендер framebuffer в сетку `5×3` и long polling управляющих стикеров.

## Подтверждённые результаты

- целевая сетка экрана `5×3` проверена на клиенте Telegram;
- Telegram-клиент может продолжать показывать закэшированную версию пака после
  успешной замены стикеров через Bot API;
- чтобы принудительно получить актуальную версию, достаточно открыть настройки
  стикерпаков и переместить нужный пак в списке;
- дальнейшая версия будет запускать игру сразу, без стартового меню.

## Целевая раскладка

Первые 15 позиций — цельный игровой framebuffer, нарезанный на сетку `5×3`.
Последние пять позиций не заменяются и используются как общий контроллер:

```text
00  01  02  03  04
05  06  07  08  09
10  11  12  13  14
LEFT RIGHT  GO  FIRE USE
```

Движок будет запускаться с `-warp 1 1`, поэтому после старта процесса сразу
появляется E1M1, без заставки и главного меню. IWAD передаётся локальным путём и
не хранится в Git.

Программа работает как CLI-воркер от имени Telegram-бота:

- создаёт тестовый статический стикерпак или подключается к существующему;
- генерирует WEBP-стикеры `FRAME 001`, `FRAME 002`, …;
- последовательно заменяет один слот или несколько слотов;
- перед каждой заменой заново читает пак, чтобы использовать актуальный
  `file_id`;
- сохраняет текущие `file_id` в JSON;
- пишет каждый вызов Bot API, его длительность и ошибки в JSONL-журнал.

## Требования

- Node.js 20 или новее;
- `clang` и `make` для native-сборки DoomGeneric;
- бот, созданный через [@BotFather](https://t.me/BotFather);
- ваш числовой Telegram user ID;
- локальный IWAD: shareware `doom1.wad`, Freedoom Phase 1 или купленный Doom IWAD;
- бот должен иметь username;
- новый `STICKER_SET_NAME` должен оканчиваться на `_by_<bot_username>`.

Telegram разрешает боту изменять только тот набор, который был создан этим
ботом. Существующий набор также должен принадлежать `OWNER_USER_ID`.

## Настройка

```bash
npm install
git submodule update --init --recursive
npm run build:native
cp .env.example .env
```

Заполните `.env`:

```dotenv
BOT_TOKEN=123456789:token-from-botfather
OWNER_USER_ID=123456789
STICKER_SET_NAME=doom_refresh_probe_by_your_bot
STICKER_SET_TITLE=DOOM Sticker Refresh Probe
DOOM_WAD_PATH=/absolute/path/to/doom1.wad
```

Не коммитьте `.env`: он уже добавлен в `.gitignore`.

### Как узнать `OWNER_USER_ID`

Напишите своему боту любое сообщение, затем временно откройте:

```text
https://api.telegram.org/bot<BOT_TOKEN>/getUpdates
```

Возьмите положительное число из `message.from.id`. Не используйте ID группы.

## Первый запуск

Создать новый пак из пяти тестовых слотов или подключиться к уже существующему:

```bash
npm run dev -- init
```

Создать пак с количеством слотов, достаточным для позиций `0..14`:

```bash
npm run dev -- init --slot-count 15
```

`init` не перезаписывает существующий пак. Если `STICKER_SET_NAME` уже
существует, программа проверит его, загрузит текущие позиции и сохранит их в
`data/state.json`.

Добавить после экрана пять постоянных управляющих стикеров:

```bash
npm run dev -- prepare-game
```

Команда требует минимум 15 экранных слотов и последовательно добавляет позиции
`15..19`: `LEFT`, `RIGHT`, `GO`, `FIRE`, `USE`. Повторный запуск безопасен:
уже существующие контролы проверяются по позиции и emoji.

Проверить подключение и состояние:

```bash
npm run dev -- status
```

## Одиночная замена

Десять раз заменить нулевой слот. Интервал — 10 секунд между плановыми
моментами начала итераций:

```bash
npm run dev -- single --slot 0 --count 10 --interval 10000
```

Если вызовы Telegram занимают дольше интервала, следующая итерация начинается
сразу после завершения предыдущей. Запросы не выполняются параллельно.

## Пакетная последовательная замена

Три цикла. В каждом цикле последовательно заменить слоты `0..4` одним номером
кадра:

```bash
npm run dev -- batch --slots 0,1,2,3,4 --count 3 --interval 30000
```

Добавить паузу 500 мс между слотами внутри одного цикла:

```bash
npm run dev -- batch --slots 0,1,2,3,4 --count 3 --interval 30000 --slot-delay 500
```

По умолчанию первая ошибка останавливает эксперимент. Чтобы залогировать ошибку
и продолжить со следующего слота:

```bash
npm run dev -- batch --slots 0,1,2,3,4 --count 3 --continue-on-error
```

## Что измеряется

Журнал по умолчанию находится в `logs/api.jsonl`. Каждая строка — отдельный
JSON-объект. Запись `api_call` содержит:

- `method`;
- `startedAt` и `finishedAt`;
- `durationMs`;
- HTTP-статус;
- `ok`;
- код, описание и `retry_after` при ошибке Telegram.

Токен бота, содержимое изображений и полные параметры запросов в журнал не
попадают.

Дополнительные события `cycle_start`, `replacement`, `replacement_error` и
`cycle_end` позволяют сопоставить серверное принятие замены с тем, когда новый
стикер появился на каждом клиенте.

## Запуск игры

После `prepare-game`:

```bash
npm run dev -- play
```

`play` выполняет следующий цикл:

1. запускает native DoomGeneric сразу на E1M1 через `-warp 1 1`;
2. публикует начальный framebuffer в экранные позиции `0..14`;
3. удаляет старый backlog Bot API, чтобы после перезапуска не повторять давние
   действия;
4. получает новые стикер-сообщения через `getUpdates`;
5. распознаёт управление по стабильному `file_unique_id`;
6. удерживает соответствующую клавишу несколько игровых кадров;
7. получает новый framebuffer и последовательно заменяет 15 экранных плиток.

Остановить процесс можно через `Ctrl+C`. В группах бот должен получать обычные
сообщения со стикерами; при включённом Privacy Mode безопаснее использовать
личный чат с ботом либо отключить Privacy Mode через BotFather.

Telegram-клиент может продолжать показывать старую версию пака. Для
принудительного обновления откройте настройки стикерпаков и переместите нужный
пак в списке.

IWAD, runtime-файлы, последние кадры и конфигурация Doom сохраняются только в
игнорируемой папке `data/` и не попадают в Git.

## Сценарий тестирования на нескольких клиентах

1. Выполните `init` и откройте напечатанную ссылку
   `https://t.me/addstickers/<STICKER_SET_NAME>`.
2. Добавьте пак на двух телефонах и в Telegram Desktop.
3. Синхронизируйте часы устройств или снимайте все экраны одним видео.
4. Оставьте панель стикеров открытой на первом клиенте.
5. На втором закрывайте и заново открывайте панель после каждой ожидаемой
   замены.
6. На Desktop переключайтесь между этим и соседним паком.
7. Запустите одиночный тест с интервалом 10 секунд.
8. Для каждого клиента запишите:
   - появился ли кадр без закрытия панели;
   - время появления `FRAME NNN`;
   - потребовалось ли переключение паков;
   - были ли пропущены или переставлены кадры.
9. Запустите пакетный тест. Следите, показывают ли клиенты смесь старых и новых
   слотов и в каком порядке обновляются позиции.
10. Сопоставьте видео/наблюдения с `startedAt`, `finishedAt` и `durationMs` в
    `logs/api.jsonl`.

Рекомендуемый первый прогон:

```bash
npm run dev -- single --slot 0 --count 12 --interval 10000
npm run dev -- batch --slots 0,1,2,3,4 --count 3 --interval 30000 --slot-delay 500
```

## Файлы состояния

`data/state.json` хранит последний известный `file_id`, `file_unique_id`,
позицию, номер кадра и следующий глобальный номер. Перед каждой заменой
программа вызывает `getStickerSet`, поэтому ручное изменение JSON не требуется.

Файл `data/state.json.lock` предотвращает два одновременных запуска, которые
могли бы менять один пак конкурентно. После штатного завершения он удаляется.
Если процесс был аварийно завершён и больше точно не работает, удалите только
этот `.lock`-файл вручную.

## Сборка и проверки

```bash
npm run build
npm test
npm run build:native
```

Реальный локальный smoke-test движка с доступным IWAD:

```bash
DOOM_WAD_PATH=/absolute/path/to/doom1.wad npm run smoke:native
```

Smoke-test запускает E1M1, получает начальный кадр, применяет `forward` и
проверяет генерацию 15 WEBP-плиток.

Для запуска собранной версии:

```bash
npm run build
npm start -- status
```

## Ограничения прототипа

- обновления всегда последовательные;
- автоматических повторов при rate limit нет: ошибка и `retry_after`
  фиксируются как часть эксперимента;
- видимость нового кадра определяется кэшем конкретного Telegram-клиента и не
  подтверждается Bot API;
- процесс использует long polling, а не webhook;
- одновременно должен работать только один экземпляр `play`;
- звук отключён, поскольку стикерпак передаёт только framebuffer и управление.

DoomGeneric подключён как закреплённый Git submodule и распространяется по
GPL-2.0.

Актуальные методы:
[Telegram Bot API — Stickers](https://core.telegram.org/bots/api#stickers),
включая `getStickerSet`, `createNewStickerSet` и `replaceStickerInSet`.
